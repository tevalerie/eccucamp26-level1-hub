The crew shown here is six agents in a straight line. Yours almost certainly differs. The pattern does not change:

  • Fewer agents? Fewer nodes, fewer edges. A three-agent org is a perfectly good org — three functions and two arrows.

Step 7 of 20 · The RAG agent 2/12

Load your client's real documents

You write this

In the setup card you typed in two or three short rules by hand. That was fine for a test. It is not how a real client bot works.

Real documents are long. A handbook, a policy page, a list of FAQs. You cannot store a whole document as one lump, because then a search returns the whole thing — and "here is all 40 pages" is not an answer.

So you cut it up first. That is called chunking. Each piece becomes one record, and a search returns the piece that answers the question.

LangGraph does this for you
  • Turns every chunk into a vector for you — no embedding model to pick.
  • Stores and indexes them all, and keeps them searchable.
  • Splits on sensible boundaries, so it does not cut in the middle of a word.

Watch out — Chunks that are too big or too small

Too small (say 50 tokens) and you get back scraps too short to answer from. Too big (say 3,000) and the one useful sentence is buried in noise the model has to wade through. 500 with 50 overlap is a good starting point — adjust once you see real results.

Your turn — in your FestPass bot

This is where the FestPass Golden Record becomes your bot's memory.

Replace the handbook text with your client's real documents. Your pod already collected them — the policies, the FAQs, the rules. Paste them in, or read them from a file.

  • Chunk size: 500 is a good default. If your client's documents are dense — tax rules, bank terms — try 300 so each piece stays on one idea.
  • The source field: name the document it came from. You will use that in the showcase to show where an answer came from.
  • The id: keep it predictable, like policy-0, policy-1. If you reload the same document, matching ids overwrite instead of creating duplicates.

Watch out for duplicates. Run this cell twice with random ids and every chunk goes in twice. Your searches then return the same text three times and the grader sees no problem with it.

Step 8 of 20 · The RAG agent 3/12

Turn retrieval into a tool

You write this

This is the moment your bot stops being basic RAG. Until now you called the search. Now you wrap it in @tool and hand it to the model — and the model decides whether to use it.

Read that docstring carefully. It is not a comment. @tool hands it to the model as the tool's description, and it is the entire basis on which the model decides to call this or not. It is the sign on the shop door.

LangGraph does this for you
  • Reads your function signature and builds a tool schema from it.
  • Hands your docstring to the model as the description.
  • Runs the function when the model asks — and only then.
  • Wraps whatever you return into a tool message on the conversation.

Watch out — The tool does not run every turn

This is the number one misunderstanding. Adding a tool does not mean it fires on every question — it fires when the model asks for it. Type "hello" and it should never run. If it does, your docstring is too broad.

The four mistakes everyone makes

1 · Expecting the tool to run every time

It runs when the model asks. If a greeting triggers a search, fix the docstring, not the wiring.

2 · Mixing up node functions and routing functions

Nodes return state: return {"messages": [...]}. Routers return a node name: return "generate_answer". Hold that pattern and half your errors vanish.

3 · Forgetting compile()

workflow is the blueprint; graph is the built thing. You invoke the graph.

4 · Leaving the loop uncapped

The one that costs money. Add a counter to the state, stop at three, answer honestly with what you have.

MAX_RETRIES = 3


def grade_documents_with_limit(state) -> str:
    if state.get("retry_count", 0) >= MAX_RETRIES:
        return "generate_answer"     # give up gracefully, and say what you don't know
    # ... the usual grading ...


def rewrite_question_with_counter(state):
    result = rewrite_question(state)
    result["retry_count"] = state.get("retry_count", 0) + 1
    return result
