變成顧問公司的營隊

這一年，虛擬客戶換成了真正的企業客戶，50 名以上的營隊學員取得 freeCodeCamp Python 認證。

向下捲動閱讀

2026 年，有些事情變了，但變的不是程式碼。營隊學員依然學 Python。改變的是另外兩件事，而這兩件事都讓賭注變得更高。

第一件事，是他們為誰而打造。

往年用的是虛擬客戶：一個看似可信、為了練習而虛構的機構，它不會失望，因為它根本不存在。2026 年換成了真實的客戶——而且不是小客戶。十一個企業客戶：銀行、一個港務管理局、一個水務管理局、數個稅務部門、一個國民保險機構。這些機構有真實的顧客、真實的義務與真實的聲譽；它們發布需求書、收下團隊打造的成品，然後親自評判。

這一換，下游的一切都跟著改變。虛擬客戶沒辦法告訴你，你的答案會讓他們難堪。真正的銀行可以，而且真的這麼說了。

第二件事，是他們結業時帶走的認證。

以往各梯學員結業時，拿到的是某個可信的線上機構或平台所頒發的 Python 證書。今年，學員參加了 freeCodeCamp 官方的 Python 考試，50 名以上的學員取得 Python 認證——一項全球認可、可公開查驗的資格，每位通過的學員都有專屬的證書網址。

差別在於這項認證對你的要求。freeCodeCamp 的 Python 認證，必須完成相當份量的專題才能取得——大約三百個小時——其中的認證專題尤其要求把整套課程實際應用出來，而不是照著步驟跟做。學員完全不必付費。最後還會得到一個公開、可分享的驗證連結。

這樣的組合很少見：一項免費就能考、卻很難考到，而且任何人——雇主、大學、客戶——都能自行查驗的認證，不必相信營隊的一面之詞，也不必相信學員的。

它也在不知不覺中，成了營隊為他們接下來的挑戰所能做的最好準備。以專題為先的認證，和真正的企業需求書，要求的是同一件事：不是你有沒有跟上課程，而是你能不能把東西做出來。

各團隊的編組就像小型科技公司。每隊都有一個客戶。每隊都有一份公布在看板上、人人都能閱讀的需求書。課程則是逆向設計的：引導師不是一路沿著 Python 語法往前推進、最後才走到某個專題，而是從一個完成的產品出發，倒推出它需要哪些 Python。你學迴圈，是因為你的機器人需要迴圈，而不是因為下一課剛好輪到迴圈。

這個轉變始於一場規劃會議，起因是一個聽起來近乎離經叛道的問題。Can I be the devil's advocate for a moment?（「我可以先唱個反調嗎？」）營隊引導師兼資訊支援人員 Telbert Pyke 問道。Have we thought about feeding all of this information into one of these known AI.（「我們有沒有想過，把這些資訊全部餵給其中一個大家熟知的 AI？」）

這個問題背後的意涵，值得細細思量。如果一個通用型助理已經能回答顧客的問題，那麼一整個營隊的青少年，到底在打造什麼？這個計畫得出的答案——並且接著花了二十天去證明——是：通用模型什麼都會回答，包括它自己編造出來的東西，而機構不可能為這種東西掛上自己的名字。各團隊打造的不是智慧，而是當責：知道自己的事實從何而來、拒絕回答職權範圍以外的問題，並在事關重大時把你轉交給真人的機器人。

為什麼企業要這樣打造

這不是為了教學而做的簡化。這正是檢索架構與代理式架構之所以存在於業界的根本原因。

銀行不能部署一個會即興編出餘額的系統。稅務部門不能部署一個會即興編出稅務規定的系統。一旦機構必須為自家軟體說的話負責，消費型聊天機器人的模式——單一模型、憑記憶作答、一步完成——就不再能夠部署。取而代之的是兩種模式，而這兩種都在這套課程裡。

檢索增強生成把模型從答案的來源，變成通往答案的介面。事實存放在機構自己擁有並管理的語料庫裡——政策通函、公告的收費標準、法規條文、費率表——系統先從這個語料庫檢索，再開口回答，並說明答案的出處。它的價值不在於讓模型更聰明，而在於讓模型可稽核：有人問某個數字從哪裡來，得到的是一份文件，而不是聳聳肩。這就是為什麼營隊的第一條規則是：事實必須先有來源，機器人才能說出口；也是為什麼黃金紀錄（Golden Record）要有一欄最後查核日期。

代理式編排把工作拆成一個個節點，每個節點都有明確的職責與清楚的交接——分類請求、檢索、檢核法規遵循、查核、升級處理——而不是要求單一模型一口氣包辦所有事。每一步都可以單獨加上限制、記錄與測試，而且任何一步都可以拒絕或轉交。這就是「產出一個答案」與「執行一套流程」的差別，而流程，正是機構可以施加控管的東西。

這兩種模式存在的理由相同，而那個理由不是精巧，而是法律責任。檢索換來的是出處；編排換來的是控制。兩者合起來，才讓語言模型成為受監管機構真正敢掛上自己名字的東西。

這也是為什麼同樣的形態，會在本書的每一件作品中反覆出現。W.E.S 在沒有有效權杖時拒絕回傳餘額。A.I.D.A. 為每一筆稅額估算附上強制性的免責聲明，並把較困難的問題轉到員工控制台。ASPIRE AI 在代理於測試中打結之後，加上了輸出結構驗證器。PILOT 在顯示資料來源時註明每一項最後查核的日期，並把任何涉及海關的問題轉交給真人調度員。

這些都不是新手的花招。它們是這個領域的實務做法，而得出這些做法的，是一群青少年——因為他們有真實的客戶，所以也有了真正需要這些做法的理由。

這是顧問公司面對的問題，而不是程式練習。也正因如此，到了 8 月下旬，好幾支由青少年主導的團隊，能夠站在一個區域性的技術評審團面前，接受關於提示詞注入（prompt injection）的交叉詰問。
