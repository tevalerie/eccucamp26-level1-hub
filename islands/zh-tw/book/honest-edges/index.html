誠實的毛邊

八道毛邊，公開承擔——以及為什麼它們正是這個計畫本身，而不是計畫的失敗。

這是本書的脊梁，也是這項計畫值得著書記述的原因。

一個只報告成功的營隊，等於在教導參與者：唯有成功才值得報告。在一個教我們藏起草稿、永遠只展示精心打磨之成品的地區，這個營隊卻毫不留情地記下了自己的每一道邊界：

課程翻轉——捨棄逐條口述 Python 語法的僵化教法，改為從完成的成品進行逆向工程。

刻意埋入錯誤的範例程式碼，迫使營隊學員親手與引擎搏鬥，而不只是看著它運轉。

第六天的重新教學，當時一次簡單的小測驗揭露，這一屆學員並不理解記憶的概念，於是一位引導員叫停了整個課表，為他們重新穩住根基。

第十三天的現場部署，因為啟動指令寫錯而當掉，隨即在台上當場修好。

ElevenLabs 點數燒光事件——語音功能刻意留在場邊坐冷板凳，而不是拿一段錄音來假裝。

多代理糾纏——六個各不相同的 AI 嚮導在多輪測試中不斷搶進彼此的發言回合；團隊以嚴格的提示詞與結構驗證器加以修正，接著在總評審的直接質詢下公開坦承。

位置判定的邊界案例，寧可暫不投入正式環境，也不為了速成的戰果而帶著缺陷上線。

最後的簡報——明明可以選擇一份完美無瑕、穩妥安全的投影片，卻寧願冒險，在滿堂來訪的大使面前，展示未經修飾的原始 Python 程式碼。

這些都不是計畫的失敗。它們就是計畫本身。一位曾在滿堂同儕與貴賓面前，現場為故障系統除錯的年輕學員，與困難之間會建立起一種截然不同的關係。

他們越過了對犯錯的恐懼，直接投入把事情做對的實際功夫。

在我們的教室裡，我們常被訓練去追逐滿分、害怕紅筆，即使根基正在搖晃，也要表演出篤定。但軟體不在乎禮數，也不在乎名望；它只在乎真相。

從失敗中前進

從失敗中前進，不是參加獎的替代說法——它實實在在就是讓最終產品變得更好的那個工程迴圈。

不先看清系統會在哪裡碎裂，就不可能打造出堅不可摧的系統。這項計畫要求這些年輕學員在台上承認自己的故障、分析殘骸、即時迭代，因而取得了更優異的技術成果，同時也打造出某種深刻得多的東西。它鍛造出一整個世代：能夠站在故障系統的正中央，目光清明、毫無愧色，隨時準備動手打造修正方案。
